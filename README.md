# Data interdependencies in the global biodiversity data ecosystem

This repository contains the data-curation, text-mining and analysis code for the manuscript **Data interdependencies expose vulnerabilities in the global biodiversity data ecosystem**.

The workflow retrieves literature relevant to targets 1-8 of the Kunming-Montreal Global Biodiversity Framework, filters and parses eligible publications, extracts named data resources and holders, standardizes their identities, and analyses international dependencies in their use.

## Repository structure

- `dataset_curation/`: literature retrieval, screening, PDF parsing and ModernBERT prefiltering.
- `text_mining/`: manual-coding samples, LLM extraction and validation, source standardization, holder coding, network analysis and figure preparation.
- `text_mining/prompts/`: the versioned system prompt used for data-source extraction.
- `project_config.py`: shared, machine-independent path configuration.
- `requirements.txt`: Python dependencies reconstructed from the active notebooks and scripts.

Exploratory notebooks, superseded scripts, notebook checkpoints, compiled Python files and generated outputs are deliberately excluded. The original working files are retained outside this publication repository.

## Setup

Python 3.11 or 3.12 is recommended.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Set the external data directory before starting Jupyter. This keeps large, restricted and generated files outside version control.

```powershell
$env:DATA_INTERDEPENDENCIES_DATA_ROOT = "D:\path\to\interdependence_data"
jupyter lab
```

The notebooks locate this repository automatically. If `DATA_INTERDEPENDENCIES_DATA_ROOT` is not set, they use the ignored local directory `data/` inside the repository.

API credentials must be supplied as environment variables and must never be written into notebooks:

```powershell
$env:LENS_API_KEY = "your Lens API key"
$env:OPENAI_API_KEY = "your OpenAI API key"
```

An illustrative variable list is provided in `.env.example`; the code does not automatically load `.env` files.

## Workflow

Run the notebooks in their numbered order, beginning with `dataset_curation/1.get_texts_linked_to_keywords_from_lens.ipynb`. The dataset-curation sequence ends with the ModernBERT-filtered publication texts. Continue with the numbered notebooks in `text_mining/`.

The principal downstream order is:

1. Create and evaluate the manual-coding sample.
2. Develop and validate the LLM extraction prompt.
3. Apply the prompt to the filtered corpus and compile the results.
4. Standardize resource and holder names and apply the reviewed decisions.
5. Merge source information with bibliometric metadata.
6. Produce holder counts, field comparisons, dependence scores, economic-group comparisons and the temporal analysis.
7. Prepare the final Supplementary Data workbook.

Detailed file-level sequences are provided in the README files within both workflow directories.

## Data availability and expected inputs

The repository does not contain article PDFs, parsed full texts, API credentials, trained model files or intermediate datasets. These materials are either too large, generated by the workflow, subject to access restrictions, or distributed separately with the article.

The configured data directory is expected to contain folders such as:

```text
manual_data/
raw_data/
parsed_texts/
filtered_texts/
training_data/
training_data_database_identification/
llm_labelled_data/
processed_data/
visualizations/
```

The final analytical tables are distributed with the article as Supplementary Data. The exact Lens search-condition workbook used for the literature retrieval is not included in this repository and is available from the corresponding author upon reasonable request. It is required to reproduce the retrieval stage exactly.

## External services

- Literature retrieval uses the Lens API.
- PDF parsing uses a local GROBID service; its URL can be overridden with `GROBID_URL`.
- LLM extraction uses the OpenAI API and requires `OPENAI_API_KEY`.
- ModernBERT training downloads `answerdotai/ModernBERT-base` unless it is already cached.

API services and model availability can change. The notebooks record the model names, thresholds and random seeds used in the study, but exact package versions were not preserved in the original working environment. `requirements.txt` therefore documents required packages rather than claiming an exact frozen environment.
